1. Executive Summary

This frontend is a blockchain investigation console focused on case review, risk analysis, wallet investigation, fund flow visualization, and AI-assisted investigation panels. The application uses a single-page dashboard layout with a left sidebar, top status bar, and dynamic content area. The frontend is designed to consume backend APIs for case data, graph data, risk data, attribution data, and AI interpretation while keeping UI rendering clean and modular.

The project follows a component-driven approach. The main app shell keeps navigation state in the root component, while inner workspace sections render the relevant screen or investigation tab. This structure is good for backend integration because the API layer is separated from the visual components and the UI can be connected to real endpoints without major rewrites.

4. Core Frontend Architecture

  • The root app manages the current screen state using React hooks.
  • The sidebar acts as the central navigation trigger for the active main view.
  • The workspace component manages inner tabs like Overview, Transactions, Risk, Graph, AI, Timeline, and Report.
  • UI state is separated from remote API interaction, which helps backend integration stay clean.
  • Responsive layout and fixed shell structure remain consistent for desktop and later extension work.

5. Navigation and Sidebar Design

The sidebar is built as a vertical navigation list using reusable button elements and icon components. It includes:

  • Overview
  • New Investigation
  • Investigations
  • Transactions
  • Fund Flow
  • Investigation Graph
  • Risk & Fraud
  • Attribution
  • AI Investigation
  • Timeline
  • Investigation Report
  • System Status

The main item flow is: click button → update currentScreen state → render correct screen → highlight active menu item. The workspace tab flow works similarly: click tab → update activeTab state → render selected investigation panel.

6. State Management

  • Current screen is managed in the root App component.
  • Workspace tabs use local component state for inner investigation sections.
  • Transactions, graph, risk, attributions, and AI response are stored in local React state.
  • Data is loaded on mount through an async effect using the API service layer.
  • WebSocket realtime status is also handled by a dedicated effect.

7. API and Backend Integration

The frontend keeps a dedicated service boundary in the API module. This is the main integration contract.

  • Health check endpoint
  • Transactions retrieval
  • Graph data retrieval
  • Flow path retrieval
  • Attribution retrieval
  • Risk score retrieval
  • AI summary and AI explanation endpoints
  • Realtime websocket endpoint generation

Environment variables are used to configure the backend base URL and websocket connection, which keeps the frontend ready for backend deployment without embedding hardcoded service URLs.

8. User Experience and Interface Design

The UI emphasizes investigation-first experiences:

  • dark dashboard theme for operations console feel
  • strong visual hierarchy for case/security information
  • clear left navigation for task separation
  • high-contrast risk indicators and badges
  • cards and panels for metrics, summaries, and network previews
  • clear content grouping for risk, AI, transactions, and timeline screens

The ChainGuard frontend is a modern dashboard-style investigation console built with React, TypeScript, and Vite. It is designed for operational intelligence, blockchain investigations, risk review, and AI-assisted analysis.
